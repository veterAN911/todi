# Резервные копии

Приложение умеет отправлять снапшот дел на собственный сервер. Функция
необязательна, по умолчанию выключена, сервер в этот репозиторий не входит.

## Настройка клиента

Адрес сервера вшивается в сборку:

```properties
todi.backupServerUrl=https://example.com
```

`gradle.properties` → `BuildConfig.BACKUP_SERVER_URL` → `BackupServer.url`.
Поля для адреса в интерфейсе нет: адрес принадлежит сборке, а не владельцу
телефона. Пустое значение отключает резервные копии.

## Авторизация

Вход устроен как код из письма.

```
POST /api/v1/auth/request
Content-Type: application/json

{"email":"user@example.com"}
```

Сервер отвечает 2xx на любой корректный адрес и отправляет письмо, только если
аккаунт существует. Так запрос не подтверждает существование аккаунта.

```
POST /api/v1/auth/verify
Content-Type: application/json

{"email":"user@example.com","code":"123456"}
```

Ответ:

```json
{"token":"..."}
```

Токен хранится в DataStore и переживает перезапуск. Файл с токеном исключён из
облачного бэкапа Android.

## API копий

Все запросы копий требуют заголовок:

```
Authorization: Bearer <token>
```

### Список

```
GET /api/v1/backups
```

Ответ:

```json
{
  "copies": [
    {
      "id": "c1f0...",
      "createdAtEpochMillis": 1792400000000,
      "taskCount": 12,
      "sizeBytes": 1532,
      "sha256": "..."
    }
  ]
}
```

Тела копий в списке нет. Чужая или несуществующая копия — `404`, не `403`.

### Загрузка

```
POST /api/v1/backups
Content-Type: application/json
Content-Encoding: gzip
X-Todi-Task-Count: 12
Authorization: Bearer <token>
```

Тело — gzip-сжатый JSON снапшота. Число живых дел передаётся заголовком, потому
что сервер копию не разбирает: он считает `sha256` от полученных байт и
сохраняет их как есть.

Ответ — объект копии в том же формате, что элемент списка. Клиент принимает 2xx.

Сервер обязан отклонить `409`, если `X-Todi-Task-Count` равно нулю, а у
пользователя уже есть непустая копия.

### Скачивание

```
GET /api/v1/backups/{id}
Authorization: Bearer <token>
```

Ответ — тело gzip как есть, без переупаковки.

### Удаление

Эндпоинта удаления нет намеренно: телефон не может удалить то, о чём не знает.
Старые копии подрезает сервер — рекомендуется хранить 10 последних в той же
транзакции, что и вставку.

## Формат снапшота

```json
{
  "version": 1,
  "app": "todi",
  "exportedAtEpochMillis": 1792400000000,
  "tasks": [
    {
      "id": 42,
      "title": "Позвонить в сервис",
      "dateEpochDay": 20776,
      "timeMinuteOfDay": 600,
      "note": "до 12:00",
      "completed": false,
      "createdAtEpochMillis": 1792300000000,
      "updatedAtEpochMillis": 1792390000000,
      "syncId": "3f2c...",
      "carriedFromEpochDay": 20770,
      "calendarEventId": null,
      "isGlobal": false,
      "completedAtEpochMillis": null,
      "deletedAtEpochMillis": null
    }
  ]
}
```

Правила:

- `id` сохраняются: по ним календарь сопоставляет события.
- `carriedFromEpochDay` и `calendarEventId` могут отсутствовать; при чтении
  `calendarEventId` игнорируется.
- Надгробия (`deletedAtEpochMillis` заполнен) входят в снапшот: восстановление
  должно отменять и удаления.
- Живым считается дело с `deletedAtEpochMillis == null`.

## Политика отправки

- Проверка выполняется раз в 6 часов, отправка — не чаще раза в 12 часов.
- Сеть обязательна: задача использует `setRequiredNetworkType(CONNECTED)`.
- Неизменённый список не отправляется. Отпечаток считается по тому же JSON с
  пришпиленным `exportedAtEpochMillis`, чтобы часы не меняли результат.
- Пропущенные дни не догоняются: телефон отправляет текущее состояние один раз.
- Кнопка «Создать копию сейчас» идёт мимо WorkManager, не проверяет порог в
  12 часов, но проверяет неизменность.
- Без токена воркер возвращает `success`, а не `retry`.
- Пустой локальный список не затирает непустую удалённую копию.

## Восстановление

1. Скачать и декодировать копию.
2. Проверить версию формата.
3. Снять страховочную копию текущего состояния.
4. Заместить базу целиком в одной транзакции: `deleteAll` + `insertAll`.

Слияние не выполняется: копия всегда немного отстаёт, и объединение показало бы
дела, которых человек не создавал.

## Минимальный сервер

Серверу достаточно:

- принимать и отдавать gzip без распаковки;
- считать `sha256` и размер;
- хранить копии по пользователю;
- проверять Bearer-токен;
- отвечать `404` на чужое;
- отклонять `409` пустую загрузку поверх непустой;
- хранить 10 последних копий.

Содержимое копий не нужно логировать и не нужно разбирать.
